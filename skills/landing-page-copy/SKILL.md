# Landing Page Copy

Turn a page into a conversion machine: clear positioning, compelling copy, effective structure. A landing page must convert AND be remembered — generic template pages fail at both.

**Core truth: positioning comes first.** If visitors can't tell what it is, who it's for, and why it beats the alternative, no section-level copy will save the page. If positioning is unsettled, run `positioning-messaging` first.

## Step 1 — Discovery (ask what's missing, all at once)

1. What is the product and what problem does it solve?
2. Who is the primary audience? (specific: role, company size, use case)
3. Top 3 competitors/alternatives and how you're different?
4. Current page URL or copy, if one exists?
5. Primary CTA? (sign up, trial, demo, download, buy)
6. Available social proof? (testimonials, case studies, logos, numbers)
7. Where does traffic come from, and what do visitors already know? (match the page to their awareness stage)

Mine Voice-of-Customer sources (reviews, support tickets, sales calls) for exact phrases — headlines built from customer language outperform invented ones. See the `copywriting` skill for the VoC workflow.

## Step 2 — Page Type & Structure

| Page type | Goal | Structure emphasis |
|-----------|------|--------------------|
| SaaS homepage | Trial/demo | Broad value prop + paths per intent |
| Lead-gen page | Email capture | Hero + lead magnet preview + minimal friction |
| Sales page (long-form) | Purchase | Full persuasion arc (PASTOR), heavy proof, bonuses, guarantee |
| Pricing page | Plan selection | Make the recommended plan obvious; answer "which is right for me?" |
| Webinar/event | Registration | Date/time prominence, speaker credibility, real urgency |
| App download | Install | Screenshots, ratings, store badges |
| Coming soon | Waitlist | Teaser + email capture |

**Standard SaaS/product page skeleton** (adapt, don't slavishly follow):

1. **Hero** — value prop + who it's for + CTA + trust signal
2. **Social proof bar** — logos, numbers, or a testimonial snippet
3. **Problem** — the pain, in their words (agitate briefly; "there's a better way")
4. **Solution / how it works** — 3-step process; reduce perceived complexity
5. **Benefits** — 3–6 outcome-focused blocks (never bare feature lists)
6. **Social proof deep dive** — testimonials with names + specific results, case study numbers
7. **Objection handling** — FAQ (top 3–5 real objections, each answered as a mini persuasion piece)
8. **Pricing preview or CTA section**
9. **Final CTA** — restate the primary benefit, repeat CTA with fresh framing, add risk reversal

**The slippery slide:** each section's job is to earn the next. Headline intrigues → subhead clarifies → problem resonates → solution relieves → proof convinces → guarantee removes risk → CTA closes. No dead ends.

## Step 3 — The Hero (highest-leverage section)

```
Headline:  [specific outcome, ideally with timeframe]  — ~10 words max
Subhead:   [how it works + who it's for]               — 1–2 sentences
CTA:       [action verb + what they get]               + friction reducer below
Proof:     [one trust signal]
```

**3-Second Test** — a first-time visitor must be able to answer: What is this? Who is it for? Why should I care now? If not, the hero fails.

Provide 3–5 headline variants using different angles for A/B testing:
- Outcome: "Get X without Y"
- Pain: "Stop struggling with X" / "Still doing X by hand?"
- Category: "The X for Y"
- Social proof: "Trusted by N teams"
- Transformation: "From X to Y in Z"

(Full headline formula library: `copywriting` skill, `references/frameworks.md`.)

Match the headline to the traffic source — visitors from an ad should see the ad's promise echoed above the fold.

## Step 4 — Section Copy Rules

- **Message hierarchy**: Outcome → Benefit → Feature. Lead with what they get, then why it matters, then how it works.
- **One idea per section**; build a logical argument down the page.
- **Benefits blocks**: limit to 3–6; each = outcome-led title + one supporting sentence. `[Feature] that [advantage], so you [benefit]`.
- **Testimonials**: specific results with attribution beat praise. "Increased revenue 47%" — name, role, company. Match proof to objections (doubt ROI → show ROI case study). 3 strong beat 20 weak.
- **FAQ**: source questions from real sales objections, not invented softballs.
- **CTAs**: repeat after each major value section on long pages; one *kind* of ask per page. Final CTA gets urgency only if real.
- **Objection pre-handling near the decision point**: guarantee, "no credit card required", "cancel anytime", what happens next.

## Step 5 — Conversion Completeness Check

Before delivering, verify the page has all essential conversion elements:

- [ ] Hero passes the 3-second test
- [ ] Primary CTA above the fold, impossible to miss
- [ ] Social proof present in hero region AND deep-dive section
- [ ] Problem articulated in customer language
- [ ] Benefits outnumber raw features; every feature bridged to an outcome
- [ ] How-it-works reduces perceived effort (≤4 steps)
- [ ] Top objections answered (FAQ or inline)
- [ ] Risk reversal near CTAs
- [ ] Final CTA section with fresh framing
- [ ] Single clear conversion goal — no competing asks
- [ ] Scannable: a reader skimming only headings + bold + CTAs gets the full argument
- [ ] Mobile: headline + CTA visible at 375px without scrolling; subject copy front-loaded
- [ ] All urgency/scarcity is genuine
- [ ] Meta title + description written (if relevant)

## Output Format

Deliver copy organized by section (hero → footer CTA), with:
- **Annotations** on key choices (which principle, why)
- **Headline + CTA alternatives** (2–3 each with rationale)
- **Action plan** when reviewing an existing page: numbered list of highest-impact fixes first
- **A/B test ideas**: the 1–2 variants most worth testing (headline first — biggest impact)

## Design & Build Handoff

Copy and design are one argument. When the user also wants the page built:
- Words are interface elements — wireframe with real copy, never lorem ipsum
- Design must not bury the conversion elements (CTA contrast, proof placement, scannable hierarchy)
- Hand off to frontend/design skills (e.g. `frontend-design`) for aesthetics and implementation; keep this skill as the source of truth for structure and copy
