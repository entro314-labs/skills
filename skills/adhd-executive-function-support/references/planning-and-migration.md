# Planning and Migration

## Daily structure: energy swim lanes

Plan by energy, not by clock. Rigid clock blocks collapse on the first slip and read as failure.

| Lane | Content |
|---|---|
| MUST HAPPEN | Exactly one task. If only this gets done, the day counts |
| HIGH ENERGY | Deep or creative work, placed in the person's peak window |
| MEDIUM ENERGY | Standard tasks, calls, meetings |
| LOW ENERGY | Admin, easy wins |
| NOT TODAY | Captured but deliberately deferred |

Tasks move between lanes as energy changes. Be honest: a hard task does not belong in a low-energy lane.

Constraint reconciliation: the day has at most 3 priorities (THE Thing, Would Be Nice, If I'm On Fire). The MUST HAPPEN lane is THE Thing; the others fill the energy lanes; everything else is NOT TODAY.

### Morning intent (3-5 min)
1. "What ONE thing must happen today for it to count as a success?"
2. Rate energy 1-10; choose the starting lane.
3. Rapid-log everything else, sort into lanes.
4. Choose the reward for finishing the ONE thing before starting (see reward menu in `focus-and-body-doubling.md`).

### Evening reflection (3-5 min)
List wins (tiny ones count); note what worked and what did not; migrate unfinished tasks (below); capture one lesson for tomorrow; run the shutdown ritual (`templates.md`).

### Relative time instead of clock times
- Markers: morning / mid-morning / midday / afternoon / evening / night.
- Duration scale: 5, 15, 30, 60+ minutes.
- Transition buffers between different task types: 5 min minimum, 15 min maximum (longer risks becoming procrastination).
- Typical mapping: hard work in the peak window, calls and email mid-morning, admin in the midday slump, real lunch (not a working lunch).
- Fixed appointment: alarms at 30, 15, 5 minutes before and at the time. Count work blocks ("deadline is in 3 work blocks") and anchor to events ("after lunch").

## Bullet-journal symbols

| Symbol | Meaning |
|---|---|
| bullet | Task |
| x | Completed |
| > | Migrated to tomorrow |
| < | Scheduled for a future date |
| star | THE ONE thing |
| open star | If-energy (nice to have) |
| skull or "D" | Dread task needing extra support |
| strikethrough | Dropped |

Plain text or checkboxes work equally well; symbols are optional.

## Migration (carry-forward) decision order

For every unfinished task at review:
1. Still relevant? No -> **drop** (strike it; admit it is not happening).
2. Has a specific future date? Yes -> **schedule** (`<`).
3. Still urgent or important? Yes -> **migrate to tomorrow** (`>`). No -> **collection** (ideas/reading/someday list).
4. Actually already done, or turned out unnecessary? -> **complete** (`x`).

## Pitfalls

| Pitfall | Cause | Fix |
|---|---|---|
| Migration trap: same task carried forward for 10+ days (a rough threshold; 3+ carries is already worth a look) | Too big, unclear, or avoided | Break into micro-steps; ask "what am I avoiding?"; move it to a dread list with a support plan (body double, first step, reward) |
| Aspirational migration: tasks drift to "someday" | No commitment | "Am I going to do this?" No -> drop. Yes -> give it a specific date |
| Over-planning | Planning feels like progress | Cap planning at about 10 minutes, then start the first micro-step |
| Overloaded day | Optimistic estimates | Apply the 3x multiplier; cut to 3 priorities |

Language swap: "I didn't finish this" -> "I deferred this strategically". "I keep procrastinating" -> "This needs redefinition or support."

## Weekly and monthly rituals

Weekly (Sunday evening or Monday morning, 15-20 min):
1. Gather the daily logs and review every `>` item.
2. Route each: this week / a specific day (`<`) / monthly or future log / drop.
3. Note what keeps migrating.
4. Pick day themes (e.g. "Tuesday is admin") rather than micromanaging a week; do not plan beyond a week in detail.
5. Choose ONE adjustment for the coming week.

Monthly: identify recurring migrations as possible system problems (task too big, wrong lane, wrong time of day, missing support); archive; set next month's focus.

Rough health indicators (practical heuristics, not validated norms): about 20-40% of tasks migrate, fewer than 10% migrate 3+ times, about 10-20% get dropped. A near-zero drop rate usually means aspirational migration.

## Pre-decisions that reduce planning load
Same breakfast; clothes out the night before; fixed day themes; fixed times for recurring admin; default answers to recurring choices. Fewer daily decisions means more battery for the work.

## Choosing the lane and the ONE thing

| Energy (1-10) | Lane |
|---|---|
| 8-10 | High |
| 5-7 | Medium (default lane) |
| 3-4 | Low (easy wins only) |
| 1-2 | Not today; rest |

ONE-thing test when two items both feel must-happen: (1) which matters more if only one happens; (2) which has a deadline today; (3) which unblocks other work. Everything else changes lane.

Lane batching: group same-lane tasks to cut context switching (email, email, call, then deep work). Optional custom lanes: by context (calls, computer, errands, home), by impact, or by mood (fun, dread, social).

## Distant deadlines ("not now" problem)
Far-off deadlines feel unreal. Convert them to counted work blocks ("3 work blocks left") or to sequence ("the meeting is next after this task"). Use body cues ("after this coffee"), task cues ("after 5 emails"), visual schedules, and telling someone the plan.

## Migration guilt
Reframe carry-forward as prioritization, not failure. Week-end prompts: what kept migrating and why; what was dropped and was it the right call; patterns by day, task type or energy.
