# App Store, Launch, Event and Welcome-Card Copy

## App store listings and marketing pack

### Intake (ask, or infer from repo docs)

App name and one-sentence value proposition; target user and job-to-be-done; 3-7 features and 1-3 differentiators; tone and banned words; target store(s) and operating system(s); screenshot count and theme; locale (default US English); proof (numbers, reviews, awards); claims to avoid.

### Rules

- 2-3 variants per high-impact field, then recommend one with a one-sentence rationale.
- One core value proposition across app title, subtitle, hero section and screenshot 1.
- Lead with the outcome for the user, not the feature name. Front-load the most important words in every length-limited field.
- No "#1" or "best" unless provable. Regulated domains (health, finance, kids): ask first. No competitor trademarks.
- Do not repeat keywords across fields that the store already indexes together; spend the space on distinct terms.

### Field limits (commonly cited ranges; stores differ and change them, so verify against the current store documentation before delivering)

| Field | Typical limit |
|---|---|
| App name / title | ~30 characters |
| Subtitle or short description | ~30 to ~80 characters, depending on the store |
| Promotional text (where offered) | ~170 characters |
| Keyword field (where the store has one) | ~100 bytes, comma-separated, no spaces |
| Full description | ~4,000 characters |

### Marketing pack quotas

5-10 taglines; 3 hero sections (headline + subhead + CTA); 6 feature blurbs of 1-2 sentences; 10 micro-CTAs; 10 short ad hooks; 5 social posts.

### Screenshot captions

5-8 captions of 2-5 words, optional sub-captions. Narrative order: setup -> value -> proof -> CTA. Give per-screenshot art direction. If generating backgrounds with an image model, prompt for the background only; render caption text separately so it stays editable and legible.

## Launch announcement (own channel, blog or listing page)

No source defined a platform-neutral launch format; this follows the press-release logic adapted for a direct audience.

- Headline: what it is plus the outcome for the user, in plain words.
- First paragraph: what launched, who it is for, what it replaces or fixes, how to get it today (link, price, availability).
- Then: 3-5 concrete capabilities, each with the benefit and one proof point (number, demo, quote); who built it and why in two sentences; one clear next step.
- Short-form launch listings: a tagline that states the function (no slogans), a description that says what it does in the first sentence, a first comment from the maker that gives the origin and asks a specific question. Check each platform's current length limits before delivering.

## Event copy

### Touchpoint timing

| Touchpoint | When |
|---|---|
| Name and tagline | 6-12 months before |
| Save-the-date | 3-6 months |
| Description | 3-6 months |
| Speaker bios | 2-4 months |
| Email sequences | 3-6 months, running |
| Registration page | ongoing |
| Attendee logistics | 1-4 weeks |
| On-site materials | day of |
| Post-event follow-up | 1-7 days after |

### Description order

1. Hook: the transformation or outcome.
2. Problem or opportunity: why now.
3. Value: what attendees learn, gain, experience.
4. Agenda highlights.
5. Social proof: testimonials, speaker credentials.
6. Logistics: date, time, place or platform, format.
7. CTA with an urgency element (deadline, early-bird end, capacity).

### Registration page

Lead with the outcome, not the agenda; social proof above the fold; price with early-bird savings visible; fewest possible form fields; countdown; FAQ answering objections; trust indicators (refund policy, privacy). Keep reminders fresh: each send needs a new angle (new speaker, sold-out tier, deadline).

## Unboxing welcome card

- Front: a brand statement or "Thank you".
- Back: three plain "Get started" steps and a QR code.
- QR landing page: setup video ("How to set up your [product]"), community link, optional offer.
- Ask for a review after the customer's first success, not at delivery.
